# Frontend methodology

The frontend consumes the JSON contract generated by `scripts/export_explorer.py`. It preserves source traceability through stable record IDs and links to the published methodology, data profile, taxonomy review, reporting-period review, and indicator metadata.

Reporting quality uses a fixed denominator for the complete source audit and separately labels filtered ED diagnostics. Matched cycles and numeric availability describe data presence only. Reporting verification is **Not comparable**: numeric values may exist in both workplan and progress records, but the reporting periods could not be verified as directly comparable. The dashboard therefore does not calculate outcome or effectiveness metrics.

Missing values remain unavailable; they are never converted to zero. Categories are deterministic taxonomy labels with `Other` retained and its share shown. Source text and source row references remain available in detail records. The interface makes no causal claims and does not produce scores, rankings, predictions, recommendations, or cross-unit averages.

## Counting and denominators

- Hospitals represented: distinct reporting organization IDs among selected historical and current records; not a count of physical sites.
- Historical initiatives: distinct exported idea associations in the two historical cycles. Current initiatives: selected 2026/27 current-workplan associations. One primary category per idea makes these category counts additive within their labelled cohort.
- Intervention categories: observed primary categories in the selection, including Other. This is not the size of the full configured taxonomy.
- Matched cycles: distinct accepted historical hospital–indicator cycles referenced by selected ideas. Filtering by category or status selects cycles containing those selected ideas, not independent category outcomes.
- Implementation-status coverage: historical ideas with Implemented, Not implemented or Conflicting status divided by all selected historical ideas. Conflicts count as reported coverage but never as a resolved implementation result. An empty denominator is Unavailable.
- Numeric availability: matched cycles containing numeric baseline/current values divided by matched cycles. This does not authorize a change calculation.
- Match-rate pair table: accepted matches / workplan cycle candidates for each specified year pair and scope. It is an explicitly unfiltered source audit. Filtered ED diagnostics deduplicate selected historical cycle IDs separately.
- Other share: Other historical ideas / historical ideas, shown separately for the unfiltered all-indicator source audit and selected ED records.

Historical charts pool selected 2024/25 and 2025/26 activity counts. First-cycle coverage is sparse and differs from the second cycle; these planning counts do not imply a representative time trend. Current 2026/27 plans have a separate cohort. Historical-versus-current charts compare counts for unequal reporting periods and coverage, without inferring change over time.

Global filters use exact displayed source attributes and persist in the URL. The optional report-cohort filter explicitly selects historical or current records. Chart drill-down retains the chart cohort so the table's records reproduce its counts. Conflicting year/status/cohort selections yield empty states rather than relaxing filters. CSV export applies both global filters and table search.

Hospital profile region/model labels include all distinct reported attributes within the selected records. Lessons learned are not a separate source field; source implementation notes and progress commentary remain unaltered and clearly labelled. Raw missing tokens are retained exactly. Empty fields display Unavailable; reported numeric zero stays zero.
